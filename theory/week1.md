# Теория недели 1 (SQL-база) — чек-лист

Цель: не «прочитать учебник», а закрыть дыры, которые проявятся на неделе 2.
Бюджет: 3–4 часа. Формат: 15 минут чтения → 5 минут «объясни своими словами».

## 1. Реляционная модель и гранулярность

- Таблица = множество строк, строка = один факт, колонка = атрибут.
- **Гранулярность**: «одна строка описывает что?» — сотрудника, отдел, заказ.
  После `GROUP BY` гранулярность меняется: строка = группа.
- Почему это важно: соединение двух множеств имеет смысл только когда
  понятно, что такое строка слева и справа.

## 2. Ключи и ограничения

- `PRIMARY KEY` — уникальность + `NOT NULL`, одна на таблицу.
- `FOREIGN KEY` — ссылочная целостность; варианты поведения при удалении:
  `NO ACTION` (по умолчанию), `CASCADE`, `SET NULL`, `RESTRICT`.
- `UNIQUE`, `CHECK`, `DEFAULT`, `NOT NULL` — чем отличаются.
- Зачем FK в учебной базе: он не даёт вставить заказ несуществующему клиенту.

## 3. Типы данных

- Целые: `integer`, `bigint` — когда какого хватает.
- **Деньги — только `numeric(10,2)`**, никогда `float`: `0.1 + 0.2 != 0.3`.
- `text` vs `varchar(n)` в PostgreSQL — практической разницы почти нет.
- `date` vs `timestamp` vs `timestamptz` — и почему для событий берут `timestamptz`.
- `boolean`, `serial` (автоинкремент).

## 4. NULL и трёхзначная логика

- `NULL` — это «неизвестно», а не «пустая строка» и не ноль.
- `NULL = NULL` → `NULL` (не `true`). Сравнение — только `IS NULL` / `IS NOT NULL`.
- `WHERE city <> 'Москва'` **не вернёт** строки с `city IS NULL`.
- Агрегаты игнорируют `NULL`: `COUNT(city)` считает только непустые.
- `COUNT(*)` считает строки, `COUNT(col)` — непустые значения.
- `NOT IN` со списком, где есть `NULL`, вернёт пусто — ловушка.

## 5. DDL и DML

- DDL: `CREATE`, `ALTER`, `DROP` — меняют структуру.
- DML: `INSERT`, `UPDATE`, `DELETE` — меняют данные.
- `DELETE`/`UPDATE` без `WHERE` — катастрофа; сначала `SELECT` с тем же `WHERE`.
- `TRUNCATE` vs `DELETE`.

## 6. Порядок выполнения запроса

`FROM` → `JOIN/ON` → `WHERE` → `GROUP BY` → `HAVING` → `SELECT` (окна здесь) →
`DISTINCT` → `ORDER BY` → `LIMIT`.

Следствия: алиасы из `SELECT` не видны в `WHERE`; агрегаты фильтруются в `HAVING`;
`WHERE` не умеет оконные функции.

## 7. Транзакции (уровень «что это»)

- `BEGIN` → `COMMIT` / `ROLLBACK`.
- ACID в одном абзаце: атомарность, согласованность, изолированность, долговечность.
- Зачем: чтобы «списать деньги и начислить» не выполнилось наполовину.

## 8. Индексы (уровень «зачем»)

- Индекс = структура для быстрого поиска; `PRIMARY KEY` и `FOREIGN KEY` индексируются.
- Не помогает: функция над колонкой (`WHERE lower(city) = ...`), `LIKE '%...%'`.
- Когда добавлять — после того как запрос стал медленным, а не заранее.

## Самопроверка (ответить без подглядывания)

1. Чем `numeric` отличается от `float` и почему для денег берут первое?
2. Почему `WHERE city <> 'Москва'` не покажет клиентов без города?
3. Чем `COUNT(*)` отличается от `COUNT(city)`?
4. Что произойдёт с заказами при удалении клиента, если FK объявлен с `CASCADE`?
5. Почему `ORDER BY` нужен, даже если «и так отсортировано»?

### Книги

- **Алан Бьюли, «Изучаем SQL»** (`Learning SQL`) — база: `SELECT`, соединения, агрегаты, подзапросы. Главы 1–7, читается за неделю. Лучшая книга для текущего уровня.
- **Кэти Танимура, «SQL для анализа данных»** (`SQL for Data Analysis`) — аналитические приёмы: когорты, retention, воронки, работа с датами. Недели 3–4, когда дойдёшь до метрик.
- **Ральф Кимбалл, «The Data Warehouse Toolkit»** — размерное моделирование. Недели 12+, после оффера или перед проектом по DWH.
- Если русского перевода нет — бери оригинал: обе книги написаны простым языком.
